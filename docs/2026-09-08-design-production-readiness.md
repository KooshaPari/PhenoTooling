# Design production readiness - 2026-09-08

## Scope and evidence boundary

This is a bounded local inventory of existing design and asset-production material in `koosha-phenotype`. It records filesystem and source evidence only. It is not a visual quality score, a brand brief, or authorization to redesign or publish.

## Inventory

The repository contains 162 tracked or generated visual files matching the bounded asset extensions searched (`blend`, `psd`, `ai`, `svg`, `fig`, `glb`, `gltf`, `webp`, raster images, video, GIF, and cast). The primary editable 3D source is:

- `asset-sources/netweave-local-rules-v1/scene.blend` (787,297 bytes), generated by `build_scene.py`.
- The accompanying `manifest.json` records Blender 4.4.3, FFmpeg 8.1.2, cwebp, hashes, dimensions, rights boundary, and the explicit illustrative/non-telemetry boundary.

No `.psd`, `.ai`, `.fig`, `.glb`, `.gltf`, or other editable scene source was found in the repository search. Existing web derivatives include NetWeave WebP states, WITF/GMK Arch/DSS Cipher stills, ShareCLI asciinema captures, and review screenshots. These are derivatives or evidence captures, not editable source scenes.

## Existing production paths

Observed authored/procedural modules include:

- `scripts/media/netweave-field.js` and `netweave-workbench.js`: deterministic state selection over authored WebP stills with alt text, dimensions, mobile sources, keyboard controls, and static/reduced-motion fallback.
- `scripts/media/sharecli-workbench.js`: four-state illustrative runtime model; source explicitly says it is not live telemetry.
- `scripts/media/sharecli-recording.js`: real recorded CLI catalog, revision-bound, explicitly separate from the illustrative model.
- `scripts/media/systems-plate.js` and `diagrams.js`: semantic SVG diagrams with summaries and fallback text.
- `scripts/media/layered-image.js` and `model-slot.js`: progressive image/model slots with explicit missing-model and reduced-motion behavior.
- `asset-sources/netweave-local-rules-v1/build_scene.py`: deterministic Blender authoring and background-render path.
- `scripts/stage-publication.js`, `scripts/prerender.js`, and `scripts/preview-server.js`: publication staging, static generation, and preview serving.

The existing implementation therefore combines real editable/procedural source (NetWeave), runtime procedural/semantic visuals (SVG and state modules), reviewed derivatives, and evidence screenshots. A screenshot or fallback is not evidence that an editable source exists.

## Reusable cross-GUI pipeline proposal

```text
brief + claim boundary
        -> editable source (blend/psd/ai/svg)
        -> deterministic export manifest
        -> desktop/mobile derivatives
        -> ffprobe/dimension/hash checks
        -> browser/a11y/reduced-motion review
        -> allowlisted staging
```

Every asset should carry source path, tool/version, command or script, hash, dimensions, alt text, evidence class, rights boundary, fallback, and reviewer/disposition. This is a proposal, not an assertion that all adapters exist today.

## Acceptance tests for future adapters

1. Export the same source twice and compare deterministic hashes or document the intentional nondeterminism.
2. Validate dimensions, codec, color profile where applicable, and file size with `ffprobe`/ImageMagick/WebP tools.
3. Confirm authored alt text and a text/static fallback.
4. Confirm mobile framing and reduced-motion behavior in a real browser.
5. Confirm publication allowlisting excludes source files and private evidence.
6. Record tool version, command, source hash, derivative hash, and reviewer disposition.
7. Keep GUI automation opt-in and permission-gated; do not infer a successful export from bundle presence.

## Limitations and next gate

No GUI applications were launched, no licensing stores were inspected, no network or settings changes were made, and no visual quality score was assigned. Existing design choices are source-grounded in the canonical portfolio and Technical Atelier specifications, but further production design choices require the source brief/user gate and, where relevant, visual review of the actual rendered artifact.

## Reproducibility pilot (2026-09-08)

A disposable, task-owned probe (not a portfolio asset) proved the editable-source to derivative path in 7.9 seconds:

```text
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python probe.py
    -> probe.blend (editable source, Blender 4.4.3)
    -> probe.png (128 x 128 RGBA)
/opt/homebrew/bin/cwebp -q 82 probe.png -o probe.webp
    -> probe.webp (128 x 128, 266 bytes)
```

Both commands exited 0. The probe used Blender Workbench and a deterministic cube/camera scene; it is only an adapter proof and must not be presented as finished artwork. SHA-256 values were recorded in the disposable probe directory `/tmp/design-toolchain-probe.tv2mAH/hashes.txt` (source, PNG, and WebP). The Blender log records Blender 4.4.3 and successful save/render. No repository source or output was modified.

This proves Blender background execution, editable `.blend` emission, PNG rendering, cwebp optimization, dimensions, and hash capture. It does not prove Cycles quality, Adobe export, GUI permission, license entitlement, or production visual acceptance.
