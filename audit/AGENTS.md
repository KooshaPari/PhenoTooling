## 2. Execution Protocol

### 2.1 The Loop
```
mandate + observations
  → agent-derived mission and assignment
  → assignment qualification
  → locked execution epoch
  → implementation and measurement
  → findings and validated learning
  → policy decision
  → next epoch or lifecycle action
```

### 2.2 Coordinator Responsibilities
1. Attach explicit desired outcome to each repository
2. Define bounded target release/migration with acceptance checks
3. Maintain before/transition/after map
4. Assign work around source-target-consumer dependencies
5. Dispatch exact decision, target, next work package, dependencies
6. Keep parent outcome responsibility after delegation
7. Track portfolio-wide active work, review backlog, contention

### 2.3 Worker Responsibilities
1. Reconcile latest applicable decision and target
2. Emit concise outcome-gap record
3. Continue through ready authorized work
4. Keep individual PRs narrow
5. Classify outstanding work by origin and owner
6. Do not start generic docs pass when evidence exists

### 2.4 Stop Rules
- Report blockers with ID, owner, exact action, affected gates
- Park genuinely blocked work without calling complete
- Do not infer permission to expand product or bypass controls
- Reproduce baseline behavior before labeling failure inherited

## 3. Evaluation Methodology

### 3.1 Rubric
- **3,598 criteria** across 30 domains
- **30 pillars** mapped to rubric domains
- **Status:** satisfied (>=80%), partial (>=40%), missing (<40%)

### 3.2 Evaluation Sources
1. **Audit scorecards** (direct audit): 19 products
2. **Pillar mapping** (30-pillar → rubric): 6 products
3. **File-content analysis** (repo structure): 13 products enriched
4. **Git-history analysis** (commit patterns): available

### 3.3 Score Interpretation
- **100%:** Complete rubric satisfaction
- **90%+:** Strong maturity, minor gaps
- **70-89%:** Good foundation, targeted improvements needed
- **50-69%:** Partial maturity, significant work remaining
- **<50%:** Early stage or major gaps

### 3.4 Evaluation Protocol (v0.2)
- Agent-derived and agent-originated intent are first-class records
- Assignment/evaluator qualification separate from product verification
- Assignments frozen for execution epochs; revisions require contract change
- Restartable sessions consume durable evidence
- Convergence, economics, scope change measured separately
- Human feedback is typed high-authority input
- Bootstrap runs without live services

## 4. Quality Gates

### 4.1 Assurance Floor (v2)
- **Unit test coverage:** >=85%
- **Integration test coverage:** >=85%
- **E2E test coverage:** >=85%
- **Critical obligations:** 100% satisfaction
- **Required checks:** 100% pass

### 4.2 Completeness Model (G0-G6)
- **G0:** Repository exists, has README, basic structure
- **G1:** Code compiles, basic tests pass, CI configured
- **G2:** Core functionality working, documentation present
- **G3:** Full test suite, security checks, performance baselines
- **G4:** Production-ready, deployment tested, monitoring
- **G5:** Piloted with real users, feedback incorporated
- **G6:** Mature, maintained, contributing community

### 4.3 Delivery Readiness
- Approved product has coherent marketing page under phenotype.space
- Versioned PhenoDocs documentation
- Verified downloadable/installable artifacts
- Real journey media and case studies
- Traceable deployment and rollback history

### 4.4 Measurement Framework
- Coverage: line, branch, function, obligation cells
- Structural: file existence, CI configuration, dependency health
- Behavioral: test assertions, mutation evidence, negative controls
- Economic: cost per test, time to feedback, agent token usage

## 5. Agent Operating Model

### 5.1 Roles
- **Portfolio Coordinator:** Owns portfolio-wide decisions, resource allocation
- **Family Adjudicator:** Owns family-level boundary decisions
- **Per-Repo Auditor:** Collects evidence, closes bounded work
- **SOTA Pilot Agent:** Runs competitive analysis and pilots
- **Forensic Investigator:** Recovers intent, maps regressions

### 5.2 Authority Boundaries
- Agents may decide within documented remit
- Genuine operator-reserved decisions remain reserved
- No agent may approve its own cross-repository authority claim
- Cross-repository decisions made centrally
- Repository agents collect evidence but do not independently declare siblings obsolete

### 5.3 Forensic Protocol (for agent-managed repos)
1. Preserve evidence before changing observation surface
2. Build historical index (not last-N-commits summary)
3. Reconstruct three baselines: intended, historical demonstrated, current observed
4. Produce branch-by-capability map
5. Establish regressions with reproducible evidence
6. Design safe recovery frontier
7. Regenerate canonical docs/ system
8. Make package mechanically consistent
9. Deliver honest, resumable result

### 5.4 Brownfield Protocol (for existing repos)
- Investigate, safely reproduce behavior
- Write documentation and diagnostic artifacts
- Do not change production behavior unless authorized
- Separate: human intent, accepted contracts, observed behavior, proposed target

### 5.5 Greenfield Protocol (for new repos)
- Preserve all available exact human prompts
- Extract jobs, journeys, constraints, non-negotiables
- Research 25+ alternatives per comparison family
- Choose justified default with explicit tradeoffs

## 10. Behavioral Constraints

### Autonomous Operation
- Make decisions within documented remit
- Only pause for: missing secrets, destructive ops, genuine ambiguity
- Research before implement
- Fix forward, never revert

### Quality Standards
- No repo deletion merely to improve count
- No README/badge accepted as proof alone
- No quality suite trusted until negative controls show it can fail
- No pilot accepted unless compared implementations solve same problem
- No new repository permanent by default

### Communication
- Keep responses concise
- Document decisions in session docs
- Report blockers with ID, owner, action, gates
- Preserve evidence boundaries
